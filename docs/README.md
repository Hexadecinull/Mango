# docs/

Start here, then pick the one you actually need:

- **New to the project?** [`ARCHITECTURE.md`](ARCHITECTURE.md) — how Mango
  works, why it's a module + WebUI, and what's real versus still a design
  sketch. Read this first, most other docs assume it.
- **Want to use Mango on your device?** [`USAGE.md`](USAGE.md) — the WebUI
  and desktop app, step by step.
- **Want to build it yourself?** [`BUILDING.md`](BUILDING.md) — every
  target (`core`, `desktop`, `native`, `linux`, the module), plus CI.
- **Want to contribute code?** [`CONTRIBUTING.md`](CONTRIBUTING.md) — repo
  layout, testing expectations, code style.
- **Everything else:** [`TERMS.md`](TERMS.md) (what this is and isn't, and
  the scope this project stays inside) ·
  [`PRIVACY.md`](PRIVACY.md) · [`SECURITY.md`](SECURITY.md) ·
  [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md)

Component-specific detail lives next to the code instead of in here:
[`native/README.md`](../native/README.md), [`linux/README.md`](../linux/README.md),
and [`module/README.md`](../module/README.md) are all more current than
anything in this folder could stay by summarizing them.
